# 澎湃内存管理优化

HyperOS3 后台保活模块，作者：雨色，版本 2.4.1。

## 功能

1. 关闭四层主动回收（mimd、mi_reclaim、unfairmem、memory_standard），停掉小米预判性杀后台，保活核心。

2. lmkd 保守化，三档阈值可调，只杀缓存进程，不碰活跃后台。

3. 全量后台保活，不需要白名单。所有第三方 App 只要进程还活着就给内核级保护（oom_score_adj 设为 -900，低于 LMK 任何档位）。保护范围是**主进程 + 消息推送通道子进程**；普通子进程（小程序容器、xweb 内核、游戏服务等）不设保护，交给系统管理和后台超时回收，避免内存大户被永久钉住。用户划掉后台时系统会杀掉进程，保护自然解除，不占内存。

4. 消息推送通道常驻保护。QQ 的 :MSF、微信的 :push、小米推送 com.xiaomi.xmsf 这类真正承担收消息的长连接进程单独识别，划掉后台也继续保护，保证不丢消息和通知。小程序容器（:appbrand）、游戏服务等非推送进程不在此列，正常回收。

5. 后台超时回收子进程。App 退到后台超过设定时长（默认 5 分钟）后，自动回收它的 :子进程（小程序、xweb 内核、游戏服务等），主进程保留，页面和状态不丢，重新进来不用冷启动。推送通道不回收。

6. 内存水位控制，内存占到设定水位才清理缓存，含迟滞避免反复清理。清理走内核定量回收接口，按 MB 指定回收量，不产生 CPU 尖峰。

7. 游戏模式，游戏前台时自动清理无关缓存后台并清文件缓存，给游戏腾内存。

8. WebUI 图形配置，液态玻璃外观，跟随系统主题，参数全中文。

9. 中文日志，分级记录加心跳，256KB 自动轮转。

纯 shell 实现，无额外依赖，不碰 CPU 调度，开销近乎为零。

## 只动第三方 App

系统应用和系统服务一律不动。判定依据是系统分区安装位置（/system、/system_ext、/product、/vendor、/odm）加包名前缀，避免误改系统组件的 oom_score_adj。

## 与其他 swap 模块共存

本模块不接管 swappiness、watermark_scale_factor 等 VM 参数，交由 Scene 等 swap 管理模块处理，避免两边抢写导致数值反复跳变。模块只做后台保活、缓存回收和游戏腾内存。
