后台保活白名单（系统级锁后台，永不被杀）
白名单内应用走系统「锁定后台」，完全不被杀，但正常参与缓存清理（只清多余内存不杀进程）。默认含微信/QQ/输入法。
lmkd 阈值（低内存时系统按这三档杀后台）
轻微压力时杀谁1001
1001 = 不杀任何进程（推荐保持，保活核心）。数字越大越保守
中等压力时杀谁950
内存开始紧张时，只杀「后台编号 ≥ 此值」的进程。900~950 = 只杀纯缓存页面
严重压力时杀谁900
内存快满时的最后防线。900 = 只杀纯缓存进程，正在前台的和常驻后台不受影响
⚠ 三档顺序必须是：轻微 ≥ 中等 ≥ 严重（例如 1001 / 950 / 900）。数值越靠右（越大）越不杀
内存水位控制
目标占用水位80
内存用到这个 % 时自动清一次缓存，让占用稳定在这个水平附近
迟滞（防抖动）5
清完后要降到「水位 − 此值」以下才停止清理，避免反复清理浪费电
单次回收内存量64 MB
每次主动清理时回收多少内存。小=更平滑但清得慢；大=清得快但单次开销高。推荐 64~128，不会造成 CPU 尖峰
后台冻结（不杀只冻）
启用系统原生冻结
开 = 后台进程冻结但不杀，点回去页面还在；微信/QQ 有消息/通知会自动解冻，不影响接收
缓存进程数量上限64
保留多少个后台在缓存态（冻结）而不是被直接杀掉。越大留得越多、点回 App 页面越不易丢，但占用内存也越高
zram 管理
接管 zram/swappiness
默认关闭，交给 scene_swap_controller
换页积极性 (swappiness)80
多大程度把不常用的内存压进 zram。0=不压（最占内存），80~100=推荐，再高会费 CPU
